# TPU 权重文件格式规范（给权重侧照做）

> 目标读者：权重/模型侧同事。本文说明「喂给 TPU 的权重二进制文件」到底长什么样、
> 每个字节怎么排、位宽和符号是什么。硬件侧已实现并验证，按此格式产文件即可对接。

---

## 0. 一句话总结

权重是 **int8 有符号**，按 **输出通道(O) → 输入通道块(cb) → 核位(KY*KX) → 块内输入通道(ci)**
的顺序连续排列（单块即 cin=C 时退化为 O → 核位 → 输入通道）；
**偏置是 int32 有符号**，逐输出通道；每层一个 **5bit 右移量 shift** 做重新量化。
激活输入也是 **int8 有符号**（像素值 −128，即 gray−128）。

---

## 1. 数据类型位宽表

| 数据 | 位宽 | 符号 | 取值范围 | 说明 |
|---|---|---|---|---|
| 权重 W | **8 bit** | 有符号 int8 | −128 ~ +127 | 卷积核参数 |
| 偏置 B | **32 bit** | 有符号 int32 | −2^31 ~ 2^31−1 | 逐输出通道一个 |
| 激活 A | 8 bit | 有符号 int8 | −128 ~ +127 | 输入特征图，gray−128 |
| 输出 O | 8 bit | 有符号 int8 | ReLU 时 0 ~ +127 | 卷积结果 requant 后 |
| shift | 5 bit | 无符号 | 0 ~ 31 | 逐层重新量化右移量 |

---

## 2. 硬约束（必须满足，否则结果错）

1. **cout 必须是 P=16 的倍数**（引擎按 `cout/P` 分组，整数除法，不整除会丢通道）。
2. **cin 必须是 C=8 的倍数**（引擎按 `cin/C` 分块，整数除法）。
   - 灰度图 cin=1 要 pad 到 8：其余 7 个通道全填 0。
3. 核尺寸只支持 **3×3** 或 **1×1**（cfg_ksize：0=3×3，1=1×1）。
4. stride 只支持 **1 或 2**；pad 只支持 **0 或 1**。
5. 每层有独立的 shift；引擎内逐层配置，多层串联由 CPU 依次配。

---

## 3. 权重的内存布局（O_CB_K_I）

一个输出通道 `co` 的权重字节流，按下面**四重**循环展开（注意：核位 `k` 在输入通道块
`cb` 之内，因为硬件一次 beat 写 C=8 个输入通道，必须先按块、块内再按核位）：

```
for co in 0 .. cout-1:              # 输出通道（最外层）
    for cb in 0 .. ncb-1:           # 输入通道块，ncb = cin/C
        for k  in 0 .. NK-1:        # 核位，NK = 3x3→9 / 1x1→1，行优先 k = ky*3 + kx
            for ci in 0 .. C-1:     # 块内输入通道（最内层，C=8 字节一个 beat）
                emit int8 weight[co][cb*C+ci][ky][kx]
```

即 **输出通道 → 输入通道块(cb) → 核位(k) → 块内输入通道(ci)** 的顺序。

> **为什么核位在通道块之内**：硬件权重写口 `w_data` 是 64bit = 8 字节，一次写**同一核位
> 的 8 个输入通道**。因此装载的原子单位是「(cb, k) 这一格的 8 个 ci」，遍历顺序必然是
> 先 `cb` 后 `k`。把 `cb`、`k` 两层合并成线性下标 `idx = cb*NK + k`，展开后的字节流与
> 「输出通道 → 核位 → 输入通道」**只在 cin=C（单块）时等价**；当 `cin > C`（多块）时，
> 如果按 `for k: for ci(0..cin-1)` 生成就会错位。**务必按上面的四重循环展开。**

### 3.1 与硬件写口的对应（一次 beat = 8 字节）

硬件权重写口 `w_data` 是 **64 bit = 8 字节**，一次写 **8 个输入通道**的同一核位：

```
w_data[ 7: 0] = 输入通道 0 的权重
w_data[15: 8] = 输入通道 1 的权重
...
w_data[63:56] = 输入通道 7 的权重
```

**字节序**：小端，`[7:0]` 是通道 0，`[63:56]` 是通道 7。

### 3.2 文件布局 ≠ 地址编码（重要澄清）

**权重文件是纯数据流，不含任何地址字段**。文件里权重区就是上一节四重循环展开后的
连续字节流。所谓「地址」（`w_addr`）是**引擎/DMA 在装载时现算的内部写地址**，
权重侧产文件时**不需要也不应该**往文件里写地址。

引擎内部地址编码（仅供理解装载顺序，权重侧无需处理）：

- `w_addr = p * WDEPTH + idx`
  - `p`    = 输出通道 lane 号（0 ~ P−1）
  - `idx`  = `cb * NK + k`
    - `cb`  = 输入通道块号（0 ~ cin/8 − 1）
    - `NK`  = 核位数（9 或 1）
    - `k`   = 核位（0 ~ NK−1）
  - `WDEPTH` = 512（权重 bank 深度）

> 装载时按 **`(p, cb, k)` 线性序**流式灌入：固定输出通道 p，先遍历所有 (cb,k)，
> 再换下一个 p。这与文件字节流的顺序**完全一致**，所以权重侧只需把四重循环展开
> 成字节流即可，无需关心地址。

### 3.3 一个 3×3、cin=8 的具体例子

以 `cout=16, cin=8, 3×3` 为例（此时 ncb = cin/C = 1，单块），权重区字节总数 =
16 × 9 × 8 = 1152 字节。

字节偏移计算公式（`co` 是输出通道，`k` 是核位，`ci` 是输入通道；ncb=1 时 cb 恒为 0）：

```
offset(co, k, ci) = co * (NK * cin) + k * cin + ci
                  = co * 72 + k * 8 + ci
```

偏移 0~71 是输出通道 0 的权重（9 个核位 × 8 通道），72~143 是输出通道 1，以此类推。

### 3.3.1 一个 3×3、cin=16 的多块例子（务必看清 cb 的位置）

以 `cout=16, cin=16, 3×3` 为例，此时 ncb = 2、NK = 9。权重区字节总数 =
16 × 2 × 9 × 8 = 2304 字节。一个输出通道 `co` 的 144 字节偏移为：

```
offset(co, cb, k, ci) = co * (ncb * NK * C) + cb * (NK * C) + k * C + ci
```

块 cb=0 占用偏移 0~71（9 个核位 × 8 个 ci=0..7），块 cb=1 占用偏移 72~143（9 个核位 ×
8 个 ci=8..15）。**顺序是 cb 外层、k 内层**：偏移 0..7 是 `cb=0,k=0` 的 ci=0..7，
偏移 8..15 是 `cb=0,k=1` 的 ci=0..7，…，偏移 64..71 是 `cb=0,k=8` 的 ci=0..7，
偏移 72..79 才是 `cb=1,k=0` 的 ci=8..15。若错按 `for k: for ci(0..15)` 生成，则偏移 8
会被写成「k=0 的 ci=8」，与硬件的 `cb=0,k=1` 完全错位。

## 4. 偏置布局

偏置 **int32 有符号**，逐输出通道一个，共 `cout` 个，连续排列：

```
for co in 0 .. cout-1:
    emit int32 bias[co]    # 4 字节，小端
```

偏置区字节总数 = `cout * 4`。

**文件布局 → 硬件写入的映射**：偏置文件里的第 `co` 个 int32 对应引擎写口地址
`b_addr = co`（0 ~ cout−1 线性编号）。引擎内部会把 `b_addr` 拆成
`bidx = b_addr / P`（组号）+ `bmod = b_addr % P`（组内 lane 号）切片存储，
这是引擎实现细节，权重侧**无需关心**——只需按「第 co 个 int32 = 第 co 个输出通道
的偏置」线性排列即可。

> 注意：偏置地址 `b_addr` 是 8 bit，因此 **cout ≤ 256**（硬件 MAX_COUT=256 上限）。

## 5. 激活输入的布局

激活输入 **int8 有符号**，值 = 像素值 − 128（灰度图 0~255 → −128~127）。

内存中按 **HWC** 布局：每个像素的 C 个通道连续，`act_data` 一次 beat 传 **8 个通道
的同一像素**（和权重一样 64bit = 8 字节）。

```
for h in 0 .. H-1:
    for w in 0 .. W-1:
        for ci in 0 .. cin-1:   # 8 个一组凑一个 beat
            emit int8 act[h][w][ci]
```

激活区字节总数 = `H * W * cin`（必须能被 8 整除）。

### 5.1 重要：激活要喂 npg 遍（DMA 模式）

引擎的计算循环是 **pg（输出通道组）最外层**：`cout/P` 个输出通道组，每算一组，
行缓冲都要**从头重填一遍激活**。因此**同一份激活数据要被喂 `npg = cout/P` 遍**。

- 在 DMA 模式下，这个多遍喂入由硬件自动完成（`act_rounds = cout/P`），权重侧
  **只需在 DDR 里放一份激活数据**，DMA 会自己重读。
- 在 CPU 直灌模式下，软件需自己重喂 `npg` 遍。

**权重侧要注意**：激活的字节数 = `H * W * cin`（**一遍的量**），不是 `npg` 倍。
多遍是硬件行为，不是数据复制。

## 6. shift（重新量化）语义

引擎内累加器是 int32。每个输出像素的累加结果 `acc` 经过：

```
sc = round(acc >> shift)   # RHA 舍入：shift==0 时直接截断，否则加 1<<(shift-1) 再右移
out = clamp(sc, -128, 127) # ReLU 时再钳到 0..127
```

`shift` 是**逐层配置的 5bit 无符号数**，权重侧需给出每层的 shift，使得
`weight(int8) × act(int8) 累加后右移 shift` 能正确还原浮点缩放。

**定标关系**（权重侧计算 shift 用）：

```
float_out ≈ (Σ int8_w * int8_act + bias) / 2^shift
```

即 shift 约等于「权重量化尺度 × 激活量化尺度」的 log2。

## 7. 完整文件布局（模型包 = load_words.bin）

一个完整模型的二进制文件按以下顺序连续存放：

```
┌──────────────────────────────────────────┐
│ 第 1 层权重区  (cout1 × NK1 × cin1 字节)  │
│ 第 1 层偏置区  (cout1 × 4 字节)           │
│ 第 2 层权重区  (cout2 × NK2 × cin2 字节)  │
│ 第 2 层偏置区  (cout2 × 4 字节)           │
│ ...                                       │
│ 第 L 层权重区 / 偏置区                    │
└──────────────────────────────────────────┘
```

各层起点偏移由 CPU 配置的 `R_WT_AB`（权重区字节基址）指定，**32 字节对齐**。
逐层 shift、H/W/cin/cout/stride/pad/ksize/relu 由 CPU 通过 MMIO 寄存器逐层配置，
**不打包进权重文件**（它们是配置项，不是数据）。

---

## 8. MMIO 配置寄存器速查（CPU 侧怎么配）

| 寄存器 | 偏移 | 含义 |
|---|---|---|
| R_CFG_HW | 0x0C | `{h[15:0], w[15:0]}` |
| R_CFG_CC | 0x10 | `{cin[15:0], cout[15:0]}` |
| R_CFG_MD | 0x14 | bit[1:0]=stride, bit[2]=pad, bit[3]=ksize, bit[4]=relu, bit[12:8]=shift |
| R_WT_AB  | 0x58 | 权重区字节基址（32 字节对齐） |
| R_WT_CFG | 0x5C | bit0=wt_en（权重走 DMA） |
| R_DMA_AB | 0x40 | 激活源字节地址 |
| R_DMA_AL | 0x44 | 激活字节数 |
| R_DMA_OB | 0x48 | 输出目的地址 |
| R_DMA_OL | 0x4C | 输出字节数 |

MMIO 基址 `0x1000_5000`。

---

## 9. 权重侧交付清单（对接时需要给硬件的）

1. **权重二进制文件**：按第 7 节布局，int8 有符号，O_CB_K_I 序（单块时即 O_KY_KX_I）。
2. **偏置**：int32 有符号，逐输出通道，跟随各层权重区之后。
3. **逐层配置表**：每层的 H/W/cin/cout/stride/pad/ksize/relu/**shift**。
4. **激活编码确认**：输入按 gray−128（像素值减 128）的 int8 有符号，还是直接
   [0,255] 的 uint8 截断到 int8？**当前硬件约定是 gray−128**，如权重侧有不同约定
   需先对齐。

## 10. 一个最小可验证示例（4 层分类网络）

`cout` 对齐 16、`cin` 对齐 8 的 4 层示例（供权重侧快速验证布局）：

| 层 | 输入 H×W | cin | cout | k | s | p | 输出 H×W | 权重字节 |
|---|---|---|---|---|---|---|---|---|
| conv1 | 32×32 | 8(灰1+补0) | 16 | 3 | 2 | 1 | 16×16 | 16×9×8=1152 |
| conv2 | 16×16 | 16 | 16 | 3 | 2 | 1 | 8×8 | 16×9×16=2304 |
| conv3 | 8×8 | 16 | 32 | 3 | 2 | 1 | 4×4 | 32×9×16=4608 |
| conv4 | 4×4 | 32 | 16 | 1 | 1 | 0 | 4×4 | 16×1×32=512 |

最后 CPU 读回 4×4×16 输出，对前 3 通道做空间平均 + argmax（FC/GAP 由 CPU 完成，
因为 TPU 只有卷积没有全连接/池化）。
