## 1. 相对 v1 做了什么

| 项 | v1 | v2 | 收益 |
|---|---|---|---|
| 行缓冲 | 每 (输出行, 输入通道块) 重填 3 整行 | 行缓冲加通道块维度，跨输出行滑行复用 | 输入带宽 3×→1×，填充周期占比 32%→11% |
| 权重 | 单份，每个输出通道组停一次等加载 | 双 bank 乒乓，计算时后台预取下一组 | 权重停顿 16455→293 周期（实测） |
| 计算阵列 | P×C INT8 MAC | 不变 | 利用率仍 100%（MAC/cyc 实测 = P×C） |

### 1.1 行缓冲滑行复用

v1 的行缓冲只有 `lbuf[3][MAX_W]`，每个字 C 字节 = 一个输入通道块。切 cb 必须重填，切 oy 也必须重填，
于是**每个输出行都要把同一批输入行反复读 3 遍**（3× 数据量，stride=2 时 1.5×）。

v2 给行缓冲加一个通道块维度：

```
lbuf [bank 0..2] [cb 0..NCBMAX-1] [x 0..MAX_W-1]   字宽 C 字节
```

所有 cb 的 3 行一次性驻留，cb 循环不再产生任何输入流量；推进到下一个输出行时只补读**新增**的
stride 行（stride=1 补 1 行，stride=2 补 2 行）。总输入流量降到恰好一遍输入特征图。

**bank 轮转映射**（关键，避免任何重命名/查表逻辑）：

- 写入侧：虚拟输入行 `vr`（可为 −1，代表 padding 行）落在 `bank = (vr + pad) % 3`
- 读出侧：窗口第 `ky` 行落在 `bank = (oy*stride + ky) % 3`

两者恒等——因为 ky 对应的虚拟行是 `oy*stride − pad + ky`，代入第一式 pad 正好抵消。
padding 行（`vr<0` 或 `vr>=H`）不消耗输入带宽，只把对应 bank 的 `bank_valid` 清零，
读出时窗口自动补零。

### 1.2 权重双 bank 乒乓

`weight_mem[2][P][WDEPTH]`，物理 bank 由 `load_bank` 选择，计算侧固定用 `pg[0]`
（第 pg 组用 bank pg%2）。时序：

```
S_WLOAD(pg=0) 等 bank0  <- 唯一的冷启动
计算 pg=0     同时请求 pg=1 -> bank1
S_WLOAD(pg=1) bank1 已就绪，零停顿通过，清就绪标记（bank1 可再次预取）
计算 pg=1     同时请求 pg=2 -> bank0（覆盖）
...
```

只有第 0 组是冷启动；只要 DMA 在上一组算完前灌完，后续组零停顿。DMA 跟不上时自动退回等待，不会算错。

握手：`pg_load_req` + `load_pg` + `load_bank`（请求）→ `w_loaded`（完成）。
`w_loaded` 取上升沿置位，避免与状态机"消费后清标记"在同一拍打架。

## 2. 接口变化（v1 → v2）

新增端口：

| 端口 | 方向 | 说明 |
|---|---|---|
| `load_pg[15:0]` | out | 请加载第几组输出通道 |
| `load_bank` | out | 请写进哪个物理 bank（0/1） |
| `NCBMAX` | param | 行缓冲的通道块维度上限，需 ≥ cin/C |

`w_addr` 语义不变（`p*WDEPTH + idx`），物理 bank 改由 `load_bank` 指定，所以驱动侧几乎不用改。
`cur_pg` 保留（调试用）。

## 3. 回归结果：18 / 18 PASS

```
python sim/tpu/run_regress.py            # 全量 18 用例
python sim/tpu/run_regress.py --quick    # 3 用例冒烟
```

用例覆盖 P/C 规模(1,4,8,16)、stride 1/2、pad 0/1、relu 0/1、方图/窄图/非方图、
ncb 1/2/4、npg 1/2/4。全部与 Python 参考模型**逐字节一致**。

关键指标（MAC/cycle 实测 = 理论 P×C，即阵列 100% 打满）：

| 用例 | P×C | comp 周期 | fill 周期 | wload 周期 | act beats | v1 需 | 带宽省 |
|---|---|---|---|---|---|---|---|
| min_p1c1 | 1 | 144 | 22 | 13 | 16 | 40 | 60% |
| p4c4_base | 16 | 2304 | 276 | 77 | 256 | 704 | 64% |
| p8c8 | 64 | 9216 | 1060 | 149 | 1024 | 2944 | 65% |
| **p16c8** | **128** | **36864** | **4164** | **293** | **4096** | **12032** | **66%** |
| p8c8_ncb4 | 64 | 10368 | 1180 | 293 | 1152 | 3264 | 65% |
| p4c4_npg4 | 16 | 2304 | 296 | 43 | 256 | 704 | 64% |
| p8c8_s2 (stride2) | 64 | 2304 | 1042 | 149 | 1024 | 1472 | 30% |

stride=2 省 27~30%，与理论 (3·hout/h = 1.5×) 吻合。

### 3.1 v1 / v2 端到端对比（P=16 C=8, 32×32×16→32, npg=2）

| 指标 | v1 实测 | v2 实测 | 变化 |
|---|---|---|---|
| 总周期 | 67535 | **43434** | **1.56×** |
| 填充周期 | 12168 | 4164 | −66% |
| 权重停顿 | 16455（2 组全灌） | 293 | −98% |
| 阵列利用率 | 54.6% | **84.9%** | +30pt |

若把 v1 的权重也改成只灌有效字数（`ncb*9` 而非整个 WDEPTH），v1 总周期约 51656，
v2 仍有 **1.19×** 提升——这部分是滑行复用带来的净收益，与权重加载方式无关。

## 4. 资源估算（PG2L200H：LUT6 159800 / FF 319600 / BRAM 415×36Kb / APM 740）

| 配置 | MAC/cyc | APM | BRAM(36Kb) | LUT(估) | 200MHz 算力 |
|---|---|---|---|---|---|
| P16 C8 | 128 | 128 (17%) | ~52 (13%) | ~10k (6%) | 25.6 GMAC/s |
| P16 C16 | 256 | 256 (35%) | ~78 (19%) | ~18k (11%) | 51.2 GMAC/s |
| P32 C16 | 512 | 512 (69%) | ~142 (34%) | ~35k (22%) | 102 GMAC/s |
| P32 C24 | 768 | 768 (>740) | — | — | 不可行 |

BRAM 拆分（P32 C16, MAX_W=256, NCBMAX=8, WDEPTH=512）：
权重 2×32×512×16B=512KB(114块) + 行缓冲 3×8×256×16B=96KB(21块) + acc 32×256×4B=32KB(7块) + bias 1块。

P×C 的硬上限来自 740 个 APM，**P32 C16 = 512 是推荐甜点**（69% APM，34% BRAM，留足布线余量）。

## 5. 已知限制 / 下一步

1. 要求 `cin` 是 C 的整数倍、`cout` 是 P 的整数倍（末块需软件补零对齐）
2. 只做 3×3 卷积；1×1（需 bypass 行缓冲）、depthwise、pooling 尚未支持
3. 每个输出通道组都要重读一遍输入（npg 倍流量），增大 P 可缓解；彻底解决需输入驻留（小图可行）
4. 累加器仍只保留一行输出（P×Wout×4B），这是大分辨率下不炸 BRAM 的前提
5. C 个乘积用加法链归约，综合时需确认 PDS 是否推断为 APM 乘加级联；频率不达标则改平衡加法树

**待办**：③ PDS 综合确认 APM 推断与 200MHz 时序　④ MMIO + AXI DMA 接入 SoC　⑤ 硬件 NMS
