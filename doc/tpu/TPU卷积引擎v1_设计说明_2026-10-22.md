# TPU 卷积引擎 v1 设计说明

日期：2026-10-22　器件：PG2L200H-6FBB676（盘古 MINI 核心板）

## 1. 定位

`tpu_conv_engine.v` 是一个**参数化 INT8 卷积加速核**，用于替代拓扑写死的
`cnn_digits_engine.v`。它不绑定任何具体网络，层参数（H/W/CIN/COUT/stride/pad/
shift/relu）全部运行时配置，因此可以逐层执行 YOLO 一类网络的卷积层。

CPU 侧零改动：本核挂在独立 MMIO 窗口上，对 CPU 而言只是一块地址空间。

## 2. 架构

```
        激活流（每 beat C 个通道的同一像素）
              │
              ▼
      ┌───────────────┐
      │  行缓冲 3×W×C │  拼 3×3 滑动窗口，padding 越界补零
      └───────┬───────┘
              │ 9 组窗口（k = ky*3+kx，逐周期轮转）
              ▼
      ┌───────────────────────────────┐
      │  PE 阵列 P×C                  │
      │   权重 bank p 吐 C 字节       │  每周期 P×C 次 INT8 MAC
      │   acc[p][ox] += Σ(bias + a·w) │
      └───────┬───────────────────────┘
              │ 累加器 P bank × Wout × INT32
              ▼
      ┌───────────────┐
      │ requant       │  RHA 舍入 + bias + shift + ReLU/INT8 钳位
      └───────┬───────┘
              ▼  每 beat P 个通道
```

**循环嵌套**（外 → 内）：

```
pg(输出通道组) → oy(输出行) → { cb(输入通道块) → [重填行缓冲] → ox(输出列) → k(9 个核位) }
```

`cb` 在内层意味着每个输出行要把 3 行输入重读 `CIN/C` 次；这是用"累加器只保留
一行输出"换来的，把片上累加器从 `P×Hout×Wout` 压到 `P×Wout`（第一层省下 6.5 MB）。

## 3. 存储组织

| 存储 | 组织方式 | 容量（P=16,C=8,MAX_W=256,WDEPTH=512） |
|---|---|---|
| 权重 | P 个 bank，bank p 存 `w[p][cb*C+0..C-1][k]`，一字 C 字节 | 16 × 64bit × 512 = 64 KB |
| 行缓冲 | 3 行 × MAX_W × C 字节 | 6 KB |
| 累加器 | P 个 bank × MAX_W × INT32 | 16 KB |
| bias | MAX_COUT × INT32 寄存器 | 1 KB |

权重只有 P 个 bank，装不下整层，所以**逐组预取**：引擎在进入每个 `pg` 前停在
`S_WLOAD` 并拉高 `pg_load_req`，外部 DMA 灌完该组权重后拉高 `w_loaded`。

## 4. 接口

| 信号 | 方向 | 说明 |
|---|---|---|
| `cfg_*` | in | 层参数，`cfg_valid/cfg_ready` 握手 |
| `w_*` | in | 权重写入，一字 C 字节，地址 `{bank_p, idx}` |
| `b_*` | in | bias 写入 |
| `act_*` | in | 激活流，每 beat C 个通道 |
| `out_*` | out | 输出流，每 beat P 个通道 |
| `w_loaded` / `pg_load_req` / `cur_pg` |  | 权重组预取握手 |
| `busy` / `done` | out | 状态 |

量化语义与既有 `cnn_requantize.v` 完全一致（RHA：四舍五入、半数远离零），
保证与旧 CNN 通路 bit-exact 对齐。

## 5. 实测结果

`sim/tpu/run_regress.py`：**14/14 全 PASS**，覆盖 P/C = 1×1 … 16×8、
stride 1/2、pad 0/1、relu 0/1、方形/窄图(W=5)/非方图(H=12,W=5)、ncb 1/2、npg 1/2。

吞吐实测（`PERF` 行，计算相内）：

| 配置 | 理论 P×C | 实测 MAC/cycle | 利用率 |
|---|---|---|---|
| P=1 C=1 | 1 | 1.00 | 100% |
| P=4 C=1 | 4 | 4.00 | 100% |
| P=4 C=4 | 16 | 16.00 | 100% |
| P=8 C=8 | 64 | 64.00 | 100% |
| **P=16 C=8** | **128** | **128.00** | **100%** |

即计算阶段**无气泡**。P=16 C=8 样例：4.72 M MAC / 36864 计算周期。

含行缓冲重填与权重加载的端到端周期：67535（P=16 C=8 样例），
即 69.9 MAC/cycle ≈ 54.6% 端到端效率。@200 MHz 约 **14 GMAC/s**；
把填充和权重预取与计算重叠后可回到 128 MAC/cycle = **25.6 GMAC/s**。

## 6. 资源估算（P=16, C=8）

| 资源 | 用量 | 占器件 |
|---|---|---|
| APM（DSP） | 128（= P×C 个乘法器） | 17% |
| BRAM 36K | 权重 16 + 累加器 4 + 行缓冲 2 ≈ 22 块 | 5% |
| LUT | 加法树 + 地址生成 + 状态机 ≈ 6k~10k（待综合确认） | 4~6% |

扩到 P=16 / C=32（512 MAC）时：APM 512（69%）、BRAM ≈ 67 块（16%），仍在预算内。

## 7. 已知限制与下一步

1. **行缓冲每个输出行重填**，未做 stride=1 的滑行复用，输入带宽多花约 3 倍。
   下一步改成循环 bank，只填新增行。
2. **C 个乘积用加法链归约**。综合时必须确认 PDS 推断为 APM 乘加级联；
   若 200 MHz 收敛不了，改例化 `ipm2l_multacc` 或手工平衡加法树。
3. **要求 CIN 为 C 的整数倍、COUT 为 P 的整数倍**，末块需外部补零对齐。
4. **权重加载与计算串行**（`S_WLOAD` 独占）。应改为双 bank 乒乓预取。
5. 尚未接入 AXI/SoC（下一版做 MMIO 包装 + DMA 描述符队列）。
6. 未做 NMS 硬件单元——按既定分工，这部分是必需的（CPU 侧 NMS 会成为瓶颈）。

## 8. 复用方式

```bash
# 生成激励 + bit-exact 参考
python sim/tpu/gen_stim.py --P 16 --C 8 --H 32 --W 32 --CIN 16 --COUT 32 --out sim/tpu/stim

# 编译 + 仿真
iverilog -g2012 -I sim/tpu/stim -o sim/tpu/tb.vvp sim/tpu/tb_tpu_conv.v myriscv/tpu_conv_engine.v
cd sim/tpu/stim && vvp ../tb.vvp

# 全量回归
python sim/tpu/run_regress.py
```
