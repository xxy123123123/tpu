## 3. TPU 卷积引擎：五代演进与当前状态

### 3.1 演进主线（P=输出通道并行，C=输入通道并行，INT8 MAC 阵列）

| 版本 | 主题 | 关键结果 |
|---|---|---|
| v1 | 参数化 P×C 阵列，串行单 MAC 的行缓冲雏形 | 14/14 通过，利用率 100% 但带宽浪费大 |
| v2 | 行缓冲滑行复用 + 权重双 bank 乒乓 | 1.56×，利用率 84.9%，输入带宽省 66% |
| v3 | 填充/计算全并行（4-bank 内容寻址）+ 1×1 卷积 | 1.72×，利用率 93.7% |
| v4 | 5-bank 内容寻址（消 stride2 bank 冲突）+ 排空/计算重叠 | **1.81×**，利用率 98.6% |
| v5 | **综合化改造**：同步 BRAM + 像素级流水（消 acc 数组） | 解决 LUTRAM 超限 124% 的致命问题 |
| v5+S3 | requant 拆独立流水级 | 估算频率 55→**76MHz**，资源全绿 |

### 3.2 当前状态（接手点）

**功能**：`sim/tpu/run_regress.py` **23/23 用例 bit-exact 全通过**，覆盖：
3×3 / 1×1 卷积、stride 1/2、pad 0/1、ReLU 开关、多输入通道块（ncb 1/2/4）、
多输出通道组（npg 2/4/8）、权重乒乓、输出背压、越界补零。

**架构要点**（`myriscv/tpu_conv_engine.v`，约 500 行，头部注释即设计文档）：
- 三级流水：S0 发射级（控制+地址）→ S1 数据级（同步读锁存）→ S2 乘加级（组合乘法+加法树→pacc）→ S3 requant 发射级
- 循环嵌套 pg → oy → ox → cb → k；每个像素的 ncb×nk 项在 P 个 32bit 寄存器 pacc 一次算完，无 acc 数组、无 drain 状态
- 行缓冲 5-bank 内容寻址（brow 行号标签并行比较），后台填充与计算/权重加载全并行
- 权重双 bank 乒乓（计算当前组时预取下一组），wmem 每 lane 独立 1D RAM
- 全局唯一冻结条件：输出背压（out_valid && !out_ready）

**P32×C16（512 MAC/cycle 甜点配置）PDS 实测**：

| 指标 | 数值 | 器件占比 |
|---|---|---|
| LUT | 12,428 | 7.78% |
| LUTRAM（分布式 RAM） | 512 | 1.30% |
| DRM（BRAM） | 128 块 | 30.84% |
| APM（DSP） | 515 个 | 69.59% |
| FF | 3,682 | 1.15% |
| 估算频率（200MHz 约束下） | **76.1 MHz** | 未达标，差 2.6× |

按 76MHz 估算吞吐 ≈ 38.9 GMAC/s，约可驱动 YOLOv5n@640 17fps（不含 NMS）。

## 5. 待办事项（按建议优先级）

### P0：冲 200MHz 时序（引擎内，预计 1~2 轮迭代）
当前 76MHz 是布局前估算（偏悲观），但 2.6× 差距需要真优化。候选：
1. **S2 加法树再拆一级**：C=16 项树拆两级（8+8），pacc 拆高低半和流水
2. **C 降到 8**：链路减半，APM 只需 256 个（仍充裕），典型面积换频率
3. **PDS synthesize opt 3 / 重定时**：当前用 opt 2
4. 跑 PnR 拿真实关键路径明细（report_timing 需 PnR 后才能出）

### P1：MMIO + AXI DMA 接入 SoC
引擎接口已就绪（act/wgt/bias/out 四个流式口 + cfg），需在 SoC 顶层挂总线从设备。
参考先例：`myriscv/cnn_mmio.v` 是 CNN 的 MMIO 接入方式，照抄结构即可。**CPU 核不动。**

### P2：硬件 NMS
YOLO 后处理必需。640 输入有 25200 候选框，93.75MHz 标量核需 50~200ms，
必须硬件化（阈值过滤 + top-K），纯 RTL 新模块，与引擎解耦。

### P3：重新综合 + 烧板
当前板上仍是旧位流（旧 3 类模型）。宽 CNN 模型 / TPU 都要新位流。
DDR3 IP 需先在 PDS 里 Generate 再综合。

## 6. 坑位清单（踩过的坑，交接给后来者）

**PDS 综合器 RAM 推断规律（探针实测，2022.2 旧流程）**：
1. generate 作用域 1D 数组 + **同步读**（读在 posedge always 里）→ 推断 DRM ✓（唯一正确写法）
2. generate 作用域 1D 数组 + 异步读（continuous assign）→ 退化 LUTRAM ✗
3. 模块级 2D 数组 + always 内 for 循环按第一维写 → **rtl-infer 段错误（signal 11）** ✗
4. 模块级 2D 数组 + generate 分 lane 写 → 不推断 RAM，退化百万 FF ✗
5. for 循环里 P 路并行读小数组（如 bias）→ PDS 复制 P 份 RAM ✗（改宽字单口存储解决）
6. `$clog2(5)=3` 位计数器 +1 不自动绕回，必须显式回绕
7. 同一 reg 被两个 always 块写 → PDS 拒绝（iverilog 容忍）——单一 always 原则
8. 循环体内未命名 block 里的 reg 声明 / function 内 `$signed` → 严格工具报错

**系统/工具坑**：
- ROM Loader 61440 字节硬上限（烧在 ROM）→ 模型权重必须 INT8 uint8 紧凑存
- GCC 引号包含优先搜源文件目录：tests 目录下的陈旧 `model_data.h` 会静默覆盖生成版（已删）
- 沙箱拦截 pds_shell 内部调的 wmic.exe → PDS 命令必须 `dangerouslyDisableSandbox`
- 沙箱拦截批量删除（rm -rf 目录树）→ 回归脚本改覆盖写模式

**TPU 架构教训**：
- padding 行（窗口越界行）的行就绪判断必须视为"就绪"（数据补零），否则按需等待死锁
- 4-bank 滑窗无法跨输出通道组保留行缓冲（pg=1 从头要行时已被覆盖）——片内放不下整图，接受 per-pg 重填靠并行隐藏
