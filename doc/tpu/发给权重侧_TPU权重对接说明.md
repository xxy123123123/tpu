# 致权重侧：TPU 权重对接说明

> 本文档由硬件侧（TPU）整理，供模型/权重侧同事对接使用。
> **本文所述数据格式已经冻结，除非另行通知，权重侧可放心据此产文件，无需担心返工。**

## 0. 格式冻结声明（先看这段）

以下内容已经通过硬件 23/23 用例回归验证 + FPGA 综合时序验证，属于**已冻结、不再变更**的
接口约定：

| 项目 | 定值 | 状态 |
|---|---|---|
| 权重位宽 | **int8 有符号**（-128 ~ +127） | 冻结 |
| 偏置位宽 | **int32 有符号** | 冻结 |
| 激活位宽 | **int8 有符号**（灰度 gray−128） | 冻结 |
| 权重布局 | **O_CB_K_I**（输出通道 → 输入通道块 → 核位 → 块内通道） | 冻结 |
| 输出通道并行度 P | **16** | 冻结 |
| 输入通道并行度 C | **8** | 冻结 |
| 对齐约束 | cout 为 16 的倍数、cin 为 8 的倍数 | 冻结 |
| requant 语义 | 累加后右移 shift（RHA 舍入） | 冻结 |

> 硬件侧承诺：后续对 TPU 的优化（时序、资源、加新算子）**均不改变上表**。
> 若未来确有变更（仅可能是 P/C/位宽三者的调整），会**提前与权重侧对齐后再动手**。

## 1. 数据位宽总表

| 数据 | 位宽 | 符号 | 范围 | 说明 |
|---|---|---|---|---|
| 权重 W | 8 bit | 有符号 int8 | -128 ~ +127 | 卷积核参数 |
| 偏置 B | 32 bit | 有符号 int32 | -2^31 ~ 2^31-1 | 逐输出通道一个 |
| 激活 A | 8 bit | 有符号 int8 | -128 ~ +127 | 输入特征图，值 = 灰度 − 128 |
| 输出 O | 8 bit | 有符号 int8 | ReLU 时 0~127；非 ReLU 取低 8 位 | 卷积结果 requant 后 |
| shift | 5 bit | 无符号 | 0 ~ 31 | 逐层重新量化右移量 |

## 2. 硬约束（违反则结果错，务必满足）

1. **cout 必须是 16 的倍数**（引擎按 cout/16 分组做整数除法）。
2. **cin 必须是 8 的倍数**（引擎按 cin/8 分块做整数除法）。
   - 灰度图 cin=1 需补到 8，其余 7 通道填 0。
3. 核尺寸只支持 **3×3** 或 **1×1**。
4. stride 只支持 **1 或 2**；pad 只支持 **0 或 1**。
5. 每层一个独立的 shift；多层串联由 CPU 逐层配置。

---

## 3. 权重的内存布局（O_CB_K_I）——最容易出错，重点看

一个输出通道 `co` 的权重字节流，按**四重循环**展开：

```
for co in 0 .. cout-1:              # 输出通道（最外层）
    for cb in 0 .. ncb-1:           # 输入通道块，ncb = cin / 8
        for k  in 0 .. NK-1:        # 核位，NK = 9(3x3) / 1(1x1)，k = ky*3 + kx
            for ci in 0 .. 7:       # 块内输入通道（最内层，8 字节一个 beat）
                emit int8 weight[co][cb*8 + ci][ky][kx]
```

### ⚠️ 关键：核位 k 在「输入通道块 cb」之内

因为硬件一次 beat 写 **8 个输入通道的同一核位**，所以遍历顺序是**先 cb、块内再 k**。

- **cin = 8（单块）**时：`cb` 恒为 0，等价于「输出通道 → 核位 → 输入通道」。
- **cin > 8（多块）**时：若错写成 `for k: for ci(0..cin-1)`，权重会**全部错位**。

> 合并 `cb`、`k` 两层为线性下标 `idx = cb*NK + k`，则字节流顺序等价于
> 「输出通道 → idx → 块内输入通道」。

### 3.1 一个 beat 的字节序

`w_data` 是 64 bit = 8 字节，一次写 8 个输入通道的同一核位：

```
w_data[ 7: 0] = 块内通道 0 的权重
w_data[15: 8] = 块内通道 1 的权重
...
w_data[63:56] = 块内通道 7 的权重
```

小端序，`[7:0]` 是通道 0，`[63:56]` 是通道 7。

### 3.2 文件是纯数据流，不含地址

权重二进制文件里**没有地址字段**，就是上面四重循环展开后的连续字节流。
所谓「地址」是硬件/DMA 在装载时现算的内部写地址，**权重侧不需要也不应该写地址**。

### 3.3 具体例子

**例 A：3×3、cin=8（单块）**，cout=16 → 权重字节数 = 16×9×8 = 1152 字节。

```
offset(co, k, ci) = co*72 + k*8 + ci
```

**例 B：3×3、cin=16（两块，ncb=2）**，cout=16 → 权重字节数 = 16×2×9×8 = 2304 字节。
一个输出通道的 144 字节：

```
offset(co, cb, k, ci) = co*144 + cb*72 + k*8 + ci
```

块 cb=0 占偏移 0~71，块 cb=1 占偏移 72~143。**顺序是 cb 外层、k 内层**：
偏移 0~7 是 `cb=0,k=0` 的 ci=0~7，偏移 8~15 是 `cb=0,k=1`，…，偏移 64~71 是 `cb=0,k=8`，
偏移 72~79 才是 `cb=1,k=0` 的 ci=8~15。

## 4. 偏置布局

偏置 int32 有符号，逐输出通道一个，共 cout 个，连续排列（小端）：

```
for co in 0 .. cout-1:
    emit int32 bias[co]     # 4 字节
```

偏置区字节总数 = `cout * 4`。第 `co` 个 int32 对应第 `co` 个输出通道的偏置。
> 注意：偏置通道编号上限 **cout ≤ 256**（硬件 MAX_COUT=256）。

---

## 5. 激活输入的布局

激活 int8 有符号，值 = 灰度 − 128（0~255 → -128~127）。内存按 **HWC** 布局：

```
for h in 0 .. H-1:
    for w in 0 .. W-1:
        for ci in 0 .. cin-1:    # 8 个一组凑一个 beat
            emit int8 act[h][w][ci]
```

激活区字节总数 = `H * W * cin`（必须能被 8 整除）。

### 5.1 激活要喂 npg 遍（权重侧只需放一份）

引擎计算循环是「输出通道组」最外层（npg = cout/16 组），每算一组行缓冲都要从头重填，
因此同一份激活会被喂 npg 遍。**这是硬件行为，不是数据复制**：
- DMA 模式下硬件自动重读，**权重侧只需在 DDR 放一份激活数据**。
- 激活字节数按 `H*W*cin`（一遍的量）算，**不要乘 npg**。

## 6. shift（重新量化）语义

引擎内累加器为 int32，每个输出像素累加结果 acc 经：

```
sc = round(acc >> shift)     # RHA 舍入：shift==0 直接截断，否则加 1<<(shift-1) 再右移
```

输出取值分两种：

- **ReLU 层**：`neg → 0`；`sc > 127 → 127`；否则取 `sc`（钳到 0~127）。
- **非 ReLU 层**：直接取 `sc` 的**低 8 位**（即按符号还原后截断，不做饱和钳位，
  值超出 -128~127 时会回绕）。

> 因此权重侧在设计 shift 时，应保证 requant 后的数值落在 int8 可表示范围内，
> 避免非 ReLU 层因截断产生溢出回绕。

shift 逐层配置，5bit 无符号。定标关系：

```
float_out ≈ ( Σ int8_w * int8_act + bias ) / 2^shift
```

即 shift ≈ log2(权重量化尺度 × 激活量化尺度)。**每层的 shift 由权重侧给出。**

## 7. 完整文件布局（模型包）

```
┌──────────────────────────────────────────┐
│ 第 1 层权重区  (cout1 × ncb1 × NK1 × 8)  │
│ 第 1 层偏置区  (cout1 × 4)               │
│ 第 2 层权重区  (cout2 × ncb2 × NK2 × 8)  │
│ 第 2 层偏置区  (cout2 × 4)               │
│ ...                                       │
└──────────────────────────────────────────┘
```

各层权重区起点由 CPU 配置（32 字节对齐）。逐层的 H/W/cin/cout/stride/pad/ksize/relu/shift
是**配置项，不打包进权重文件**，由 CPU 通过寄存器逐层配置。

---

## 8. 权重侧需要交付的清单

1. **权重二进制文件**：按第 7 节布局，int8 有符号，O_CB_K_I 序。
2. **偏置**：int32 有符号，逐输出通道，紧跟各层权重区之后。
3. **逐层配置表**：每层给 H / W / cin / cout / stride / pad / ksize / relu / **shift**。
4. **激活编码确认**：输入按 gray−128 的 int8 有符号（**当前硬件约定**），如权重侧有
   不同约定（如 [0,255] uint8 截断）需先与硬件对齐。

## 9. 硬件能力边界（选模型前必读）

TPU 是**纯卷积加速器**，只做卷积。以下是算子边界，供权重侧选模型时参考：

| 算子 | 硬件是否支持 |
|---|---|
| 3×3 / 1×1 卷积（stride 1/2，pad 0/1，ReLU） | ✅ 支持 |
| 全连接（FC） | ❌ 不支持，由 CPU 完成 |
| 池化（max/avg pooling） | ❌ 不支持，由 CPU 完成 |
| 全局平均池化（GAP） | ❌ 不支持，由 CPU 完成 |
| 上采样 / concat / 残差加法 | ❌ 不支持，由 CPU 完成 |

> 若目标模型是 YOLO，请注意其 upsample / concat 等算子需落在 CPU 侧。
> 建议优先选**卷积为主、结构规整**的轻量网络，便于充分发挥 TPU 卷积加速优势。

## 10. 硬件性能与模型规模上限

> 以下数据来自 FPGA 布局布线后的实测综合报告（盘古 MINI，PG2L200H），供权重侧
> 判断「能跑多大、多快」的模型。**只要模型满足第 2 节硬约束 + 下表规模上限，即可保证可上板运行。**

### 10.1 算力与频率

| 项目 | 数值 | 说明 |
|---|---|---|
| 阵列规模 | **P16 × C8 = 128 个 INT8 MAC** | 每个时钟做 128 次乘加 |
| 系统主频 | **93.75 MHz** | SoC 集成后运行频率（布线后时序余量 +0.542ns，上限约 98.7 MHz） |
| 峰值算力 | **≈ 12 GOPS** | 128 MAC × 93.75 MHz（INT8 乘加/秒） |
| 资源占用 | LUT +8.5k / FF +5.7k / DSP +128 | 全 SoC 中 TPU 的增量，整板余量充足（LUT 18%/FF 8%/DSP 19%） |

> 说明：引擎单独布线（P32×C16 配置）可达 148.77 MHz，但**上板运行的是 P16×C8 @ 93.75 MHz**，
> 上表以此为准。权重侧只需关注「算力数量级」，不必关心具体频率。

### 10.2 单层尺寸上限（硬性，超出则引擎无法计算）

| 维度 | 上限 | 对齐 |
|---|---|---|
| 输出通道 cout | ≤ **256** | 16 的倍数 |
| 输入通道 cin | ≤ **64** | 8 的倍数 |
| 输入宽度 W | ≤ **256** | 无 |
| 输入高度 H | 无硬上限（按行流式处理） | 无 |

> cin 上限 64 来自行缓冲的通道块维度（8 块 × 8 通道）。若模型某层 cin > 64，
> 需在该层前用 1×1 卷积降维，或与硬件侧沟通扩大 NCBMAX。

### 10.3 权重/激活存储

- 权重、偏置、激活均经 DMA 从 **DDR3（1 GB）** 搬运，**总量基本不受片上 BRAM 限制**。
- 因此模型权重文件大小**不是瓶颈**；真正的约束是上面 10.2 的**单层维度上限**。

### 10.4 单层延迟粗估

单个卷积层的计算周期约为（含流水排空，忽略首层填充开销）：

```
cycles ≈ npg × (H_out × W_out × ncb × NK)   # npg = cout/16, NK = 9(3x3)/1(1x1)
latency ≈ cycles / 93.75 MHz
```

以 64×64 输入、3×3、cin=16、cout=32（npg=2、ncb=2、输出 32×32）为例：
`cycles ≈ 2 × (32×32×2×9) = 36864` → 延迟 ≈ **0.39 ms**。全网络若干层累加，总推理延迟
通常在**毫秒级**，可满足边缘实时识别。

## 11. 最小可验证样例（供权重侧自测布局）

cout 对齐 16、cin 对齐 8 的 4 层示例：

| 层 | 输入 H×W | cin | cout | k | s | p | 输出 H×W | 权重字节 |
|---|---|---|---|---|---|---|---|---|
| conv1 | 32×32 | 8 | 16 | 3 | 2 | 1 | 16×16 | 16×9×8=1152 |
| conv2 | 16×16 | 16 | 16 | 3 | 2 | 1 | 8×8 | 16×9×16=2304 |
| conv3 | 8×8 | 16 | 32 | 3 | 2 | 1 | 4×4 | 32×9×16=4608 |
| conv4 | 4×4 | 32 | 16 | 1 | 1 | 0 | 4×4 | 16×1×32=512 |

最后 CPU 读回 4×4×16 输出，对前 3 通道做空间平均 + argmax（FC/GAP 由 CPU 完成）。
